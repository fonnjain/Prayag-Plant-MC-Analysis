How to Use

Send any active key as a header with every request:

# HTTP header (recommended)
X-API-Key: your-api-key
# Or as a query parameter
{{ base_url }}/data-api/v1/summary?period=current_fy&api_key=your-api-key

Filters (query parameters on /summary and /records):

period — e.g. last_updated, yesterday, last_month, current_fy, q1–q4, 2026-07 (month) or 2026-07-15 (day)
plant, segment, machine — narrow the scope
from_date, to_date — custom range (with period=custom)

Access From Another Web App

The API allows cross-origin requests (CORS) from any website, so a browser app can call it directly — or call it server-side from any backend. Base URL: {{ base_url }}/data-api/v1

// JavaScript (browser or Node)
const r = await fetch("{{ base_url }}/data-api/v1/summary?period=last_month", {
  headers: { "X-API-Key": "your-api-key" }
});
const data = await r.json();
# Python
import requests
r = requests.get("{{ base_url }}/data-api/v1/summary",
  params={"period": "last_month"},
  headers={"X-API-Key": "your-api-key"})
data = r.json()
• Read-only: the API can never change anything in this dashboard.
• Errors: 401 bad/missing key · 503 no key configured yet · 502 source sheets unreachable.
• Keep the key server-side when possible — anyone with the key can read all production data. If a key leaks, delete it here and generate a new one.
Data integrity: all figures are recomputed from the real production sheets — never fabricated. A ratio without a baseline returns null, never 0. If figures_gated is true, the period has unresolved data-confirmation errors — treat the figures as "needs review".
