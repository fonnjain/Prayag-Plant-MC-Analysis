## FIX 1 — Harmonise the rejection colour thresholds (templates only)

The rejection `%` badge uses **two different colour rules** across the app, so the same value is coloured differently on different pages. A 3% rejection shows **amber** on the overview but **red** everywhere else.

The correct rule is the three-tier one already used in `templates/overview.html:182`:

```
{% if X.rejection_pct < 2 %}text-green-600{% elif X.rejection_pct < 5 %}text-amber-600{% else %}text-red-600{% endif %}
```

Apply that same three-tier rule to these **five** two-tier locations (change only the colour condition — leave the surrounding markup, classes and variable names exactly as they are):

1. `templates/plant.html:142` — `m.rejection_pct`
2. `templates/report_detail.html:135` — `o.rejection_pct`
3. `templates/report_gom_summary.html:39` — `overall.rejection_pct`
4. `templates/report_gom_summary.html:75` — `row.metrics.rejection_pct`
5. `templates/report_tank_location.html:58` — `overall.rejection_pct`

Leave `overview.html:182` as-is (already correct). Do not alter the `is_mixed_unit` by-unit branch in `overview.html`.

**Note:** `rejection_pct` can be `null` (suppressed by the no-fake-0% invariant). Ensure a null value does not crash the template or render as green — keep the existing null/blank handling behaviour identical to what each template does today.
