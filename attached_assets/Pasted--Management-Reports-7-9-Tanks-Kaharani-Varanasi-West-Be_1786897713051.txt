## The layout is transposed — months run across columns

Unlike every report so far, **months are columns, not rows**, and they run **latest-first**: `JUL'26 · JUN'26 · MAY'26 · APR'26`. Each month spans **two** columns — `Production (in Ltr)` and `Rejection (in Ltr)`.

**There are TWO stacked pivot sections, each with its own TOTAL row (R-37):**

1. **By product type** — rows such as `2 Layer Light`, `3 Layer Light`, `4 Layer Light`, `2 Layer ISI`, `3 Layer Colour`, `3 Layer Heavy`, `4 Layer Colour`, `4 Layer Heavy`
2. **By tank size** — rows `500 · 750 · 1000 · 1500 · 2000 · 3000 · 5000`

Both sections cover the **same production**, split two ways, so **both TOTAL rows carry the same figure**. Parsing past the second TOTAL double-counts — that is R-37, already guarded in the Tank annual parser. Reproduce the structure, do not merge the sections.

**The row sets differ per plant.** VN shows only `2/3/4 Layer Light` and sizes `500/750/1000/2000`; KH carries the full eight product types and seven sizes. **Derive each plant's row set from its own data — do not hardcode one plant's list for another.**

## Where our figures come from

**Size** — the `SIZE (LTR.)` column in `PROD. REPORT`, read directly. Do **not** derive it from the item code: `-05` is 500 but `-07` is 750, so it is a code, not arithmetic.

**Product type** — must be derived from the item code, and **this mapping must be verified before building**. The pattern appears to be `[2|3|4]L[L|C|H]` for layers plus Light/Colour/Heavy, with `ISI` as its own grade:

```
WCT-3LC-05  ->  3 Layer Colour, 500 L
WCT-3LL-05  ->  3 Layer Light,  500 L
WT-4LL-20   ->  4 Layer Light,  2000 L
WT-ISI-10   ->  ISI,            1000 L
```

**Print the distinct item codes per plant and the product type each maps to, and confirm the totals reconcile, before wiring.** A wrong mapping silently misallocates production across rows while the TOTAL still balances — which is exactly the failure this project keeps hitting. If a code does not map cleanly, **raise a named error** (**R-06**); never assign it to a default bucket.

**Production (in Ltr)** — `PROD. REPORT`, our existing Tank path.

**Rejection (in Ltr)** — `rejected pcs × SIZE (LTR.)` (**R-09**). Do **not** sum the kilogram columns here; this section is litres. The kg basis exists separately and is already reported on the plant pages.
