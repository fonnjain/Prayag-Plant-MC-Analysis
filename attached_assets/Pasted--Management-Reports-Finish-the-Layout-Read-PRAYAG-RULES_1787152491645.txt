# Management Reports — Finish the Layout

Read `PRAYAG_RULES.md`. Repo: `fonnjain/Prayag-Plant-MC-Analysis`.

**The Cardinal Rule stands and is not in question here.** Every figure remains recomputed from live source data. **No number may change in this work.**

The QA rounds are about **structure**: sections missing, columns dropped, month rows collapsed to totals, and layouts that do not mirror the source sheet. Nothing about the figures themselves is in dispute.

**The goal: for every report, the page and the download must both mirror the source workbook's layout** — same sections, same columns, same column order, same row grain.

## The underlying cause, and the durable fix

Most of these are **key-contract mismatches**: the builder returns one field name, and the template or serialiser reads another. The lookup fails silently and the column disappears — no error, just a blank.

Two already confirmed:
- GOM's serialiser reads `section1.rows`; the builder returns `section1.fy2627[]` and `section1.fy2526[]`.
- Several sections serialise `months[ym].hrs` only, dropping `gross_kg` and `avg_hr`.

**Fix the individual mismatches, then remove the class.** A shared accessor for each cell shape, used by **both** the template and the serialiser, means a renamed field breaks loudly in one place instead of silently blanking a column in two. The `{hrs, out}` accessor already added is the pattern — extend it.

**Then add a guard:** if a section the report declares produces **zero populated columns or zero rows**, log a named warning rather than rendering an empty block (**R-06**). Every fault above was silent.
