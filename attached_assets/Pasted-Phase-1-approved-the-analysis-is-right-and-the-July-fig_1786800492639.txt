=== THE CHANGE: rejection needs a JOIN, not a switch ===

The proposal says May's 120 kg "will not appear in Phase 2 — this is the honest read."
It is not honest, and here is why:

  May's MACHINE 1 tab HAS a rejection column (TOTAL REJECTION) with every value blank.
  parse_daily_blocks sets rejection_tracked = (rej_c >= 0), so rej_c >= 0 → tracked = True.
  Result: May renders 0.00% rejection, in GREEN, while the Daily Report records 120 kg (8.76%).

That is the Garden rejection bug in a new place. Garden was rescued because the column was
ABSENT; here it is PRESENT BUT EMPTY, which the current guard does not catch (Failure Mode #14).

Neither source is complete on its own:
  JULY  block tab rejection 3,782 kg  |  Daily Report 0
  MAY   block tab rejection BLANK     |  Daily Report 120 kg

Required behaviour:
 (a) Take rejection from the MACHINE block tabs where values exist (July: 3,782).
 (b) Where a month's block-tab rejection column is entirely blank, fall back to the
     Daily Report's rejection for that machine-month (May: 120).
 (c) Where NEITHER source has a value, set rejection_tracked = False so it renders n/a —
     never a green 0.00%.
 (d) Extend the rejection_tracked guard: a column that exists but is empty for the whole
     month must not count as "tracked". Present-but-empty is not the same as zero.
 (e) Where both sources have values and they differ, surface a note (R-35). Do not pick one.
