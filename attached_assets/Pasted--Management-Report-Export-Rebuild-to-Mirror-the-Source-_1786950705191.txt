## The problem

The `.xlsx` download and the HTML pages are **two entirely separate pipelines**:

| | Route | Built by |
|---|---|---|
| Pages | `/management-reports/<name>-summary` | the thirteen `mgmt_*.py` builders |
| Export | `/management-reports/<rid>.xlsx` | `reports/registry.py` → `generators.py` → `xlsx.py` |

`management_report_download` calls `rreg.report_bytes(rid, ym)`, which never touches a `mgmt_*` builder. Those generators predate all thirteen report builds.

**So every download is producing the old content** — no new sections, no flags, no corrections, no multi-tab structure. The Cardinal Rule work is absent from the artefact people actually circulate.

## Build it from the page builders, not a parallel path

**This is the point of the exercise.** The export must call the same `mgmt_*.py` builders the pages use, so a figure can never differ between what someone sees and what they download. Do **not** write a second set of calculations.

Practically: each builder already returns a structured result. Add a thin serialiser that turns that same result into worksheets. If a builder's return shape makes this awkward, **report it rather than duplicating logic**.

Keep the existing behaviour from the current generator docstring: **recomputed VALUES, never live formulas.** No `IMPORTRANGE`, no cell references, no links back to source workbooks.

## Flags — a `Notes` tab per workbook

On the pages, divergences appear as amber badges and banners. In a spreadsheet they must survive copying, printing and forwarding.

**Add a `Notes` tab as the last sheet of every workbook**, with one row per flag:

```
Rule | Report section | Month | Our figure | Source figure | Difference | Note
```

Populate it from the same flag data the templates use — R-23, R-42 (Garden and HDPE), R-43, R-24, R-26, the KH June data errors, the sum-of-monthly TOTAL defects, the PPR-missing-from-TOTAL note, and the basis labels (gross/net, machine hours vs mould hours, daily vs annual).

**In addition, mark the affected cell itself.** Where a figure carries a flag, add an Excel cell comment with the short form (e.g. *"R-24: daily 147,835 vs annual 160,478 — separate mould chain"*) so the note travels with the number when a row is copied.

`AWAITING SOURCE DATA` must render as that text, **never as 0 or an empty cell** (**R-07**, **R-08**). Same for `n/a`, `IDLE` and `⚠ unavailable`.

## Suggestions worth taking

**A cover sheet as the first tab** — report name, the month or FY period, generation timestamp, the source workbook it mirrors, and a one-line statement that every figure is recomputed from live source data and is not copied from the workbook. That single line prevents the most likely misunderstanding when the file is forwarded.

**Number formats matching the source** — thousands separators, two decimals on per-kg and cost columns, percentages as percentages. Bold TOTAL rows. Freeze the header row and any sticky left columns. It costs little and makes the file usable without reformatting.

**Keep the ZIP bundle working** — `zip_bundle` should pick up the rebuilt reports. Confirm it still reports `built`/`total`/`skipped` honestly rather than silently dropping a failed report.

**Fail loudly on a partial build.** If a builder returns a `_failed_pairs` result or raises, the export must not write a workbook containing silent blanks. Either omit the file and list it in `skipped`, or write it with the failure recorded on the `Notes` tab. **Never a clean-looking file built from a failed read** — that is the cold-cache failure in a more dangerous form, because a downloaded file outlives the page.
