## Problem 1 — Google Sheets links in the Paid Wages column

Each month row carries a visible link reading `KH-1 payroll ·` in the Paid Wages area. These are cut off at the table edge and, per the review, **are not wanted**.

**Remove the links from the table cells.** The payroll workbook is the source and that provenance is worth keeping — but it belongs in the section note or a tooltip, not as a clickable link inside a data row.

## Problem 2 — the SUMMARY table runs off the right edge

The `SUMMARY — Monthly Labour & Output` table is cut off. Visible: Month, M/C Run Hours, Actual Output with Rej. (KG), Labour (Persons), Actual Paid Hours. **Not visible at all:** Paid Wages, Paid Hours Devoted by Per Person, Per Hour Cost on Paid Hours, Per KG Labour Cost.

The cause is the **Month column being far too wide** — it is being stretched by the long orange note on the TOTAL row:

> *Partial payroll through APR'26, MAY'26, JUN'26, JUL'26 · awaiting AUG'26*

**Fix:**
- Move that note **out of the TOTAL row cell** — put it beneath the table or in the section header, where it does not drive column width.
- Constrain the Month column to its content width.
- Make all nine columns fit without horizontal scrolling at normal window width. Right-align numerics, keep Month left-aligned.

## Problem 3 — SUMMARY-1 is squeezed by the comparison panel

The FY25-26 panel occupies roughly a third of the width, so the main table shows only Machine, Pipe Type, Ideal Hours, Actual Hours and Actual Output — with a horizontal scrollbar hiding Ideal Output, Avg Per Output on Hours, M/C Utilisation % and Output Efficiency %.

**Fix:** give the main table the full width and place the FY25-26 comparison **below** it rather than beside it. All nine columns must be visible without scrolling.

## Note on "2025-26 data is not coming"

The screenshot shows the reason:

> ⚠ *Pipe M/C 25-26 tab read failed: Google Sheets API error (429).*

That is a **transient rate-limit**, and the panel handling it correctly — *"FY25-26 comparison data not available — check Pipe M/C 25-26 tab"* is the failed-read guard working as designed, not a bug.

**Do not change that logic.** But two presentation improvements are in scope:

- Make it clearer this is a temporary read failure rather than absent data — the current wording reads like the tab is missing.
- If a retry is already available, surface it. If not, say so; **do not build one** in this pass.
