## READ THIS FIRST — what the file actually is

Its columns are:

```
A Item Code · B Item Name · C Category · D Packing · E Net Stock · F Weight/Pc (g) · G Total Weight (kg)
```

**Column E is Net Stock — finished pieces already on hand.** It is **not** a production quantity and **not** a release plan. There is no "Production Plan" column, so this file will **not** load through the normal release-plan upload (`_locate_plan_columns` looks for `Item Code` + `Production Plan` by header text).

**Totals for reference:** 236 items · **232,214 pieces** · **205,882.38 kg**.

In planning terms, stock is what gets **subtracted from demand** — it tells the planner what *not* to make. Do not treat column E as something to produce.

## Important — treat this as a stock file, not a demand file

Because column E is stock, a true production plan needs a **demand or release-plan** figure to net it against:

```
net demand = demand − net stock
```

Without a demand file, you can only show **which machines are capable of these items** — which is what Step 2 asks for. **Do not invent a demand figure to make a schedule.** If you produce anything that looks like a production schedule, state plainly that it is a **capability/routing view**, not a plan to produce, since no demand was supplied.

If a release plan for this period already exists in the system, say so — then the two can be joined properly, and I will ask for that as a separate step.
