## What makes PTMT different (the app must handle these, or fail loudly)

PTMT is **injection moulding** — structurally unlike the Plumbing/Garden pipe segments. A parser built on pipe assumptions will silently misread it.

1. **48 mould machines** (`M/C-1 … M/C-48`), each tonnage-tagged (80 / 110 / 125 / 150 / 200 / 250 / 350 / 450 / 130-TON) — not 9 pipe machines. Machine labels also carry a mould-code (e.g. `80-1`, `N-200D`).
2. **Moulding-only metrics** with no pipe equivalent: *Nett Output, Rejection, Lumps (Gulla), Runner Produce, 100% Wastage, Total Grinder Working, Runner %age, Avg Run Hour per Mould*.
3. **Two different output figures — do not confuse them:**
   - **Nett Output (KG) = 537,109** ← authoritative; use this for rejection % and cost/kg.
   - **Weight of Total Production = 541,258** ← a different (larger) basis; NOT the output figure.
4. **Date format is `1-Aug-2026`** (day-month-year), unlike Plumbing's `Aug 1, 2026`. A shared date parser must handle **both**, or raise a named error — never yield empty rows.
5. **Months run latest-first** in the summary (MAR'27 at top → APR'26 → TOTAL). Map by label, not row order.
6. **July labour is blank** despite full July output (172,639 kg) — the same orphaned-labour pattern seen in Plumbing/Garden. Flag it; do not divide into a misleading ₹/kg.
7. **~393 moulds** with per-mould **cavity / cycle-time / pc-weight** detail (the routing data if PTMT ever gets a planner). Materials span **PBT / PP / PC / PVC / ABS / LD / DALRINE / HD GREEN / LDPE / EVA / TPR / NYLONE**.
