## What makes Tank different (the app must handle these, or fail loudly)

1. **Primary unit is LITRES (tank capacity)**, not kg. Each file also carries pcs and kg, but the headline metric is Ltr. Do not force a kg basis.
2. **Three separate plant files** — the segment total is the sum of KH + VN + WB. A single-file read (e.g. KH only) understates the segment by ~10×: KH is only **9%** of Tank volume.
3. **Production-only summary** — there are **no** labour, machine-hours, or rejection-% columns like Plumbing/Garden. Columns are: ITEM CODE, COLOUR, Production (Pcs), Production (Ltr), Rejection (Pcs), Rejection (Ltr), Rejection Mouth-Lid (Kg). Rejection is small and in Ltr, not a %.
4. **Months run latest-first** (MAR'27 → APR'26 → TOTAL). Map by label, not row order. Data exists **APR–JUL 2026 only** (KH has **JUN only**).
5. **Tank sizes are the item axis**: 500 / 750 / 1000 / 1500 / 2000 / 3000 / 5000 Ltr, across types 2-Layer ISI, 3-Layer Light/Colour, 4-Layer Light/Colour. Report can roll up by size or by type.
