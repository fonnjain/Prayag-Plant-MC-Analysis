# Fix — Moulding Report Row Leakage (+ verify `tank_summary` filter)

**Scope: `REPORT_TYPES` segment config and a verification step. Nothing else.**

The diagnostic confirmed: `report_detail` applies the segment filter only when a report declares segments —

```python
rows = data["rows"]
if rpt["segments"]:
    rows = _filter_report_segments(rows, rpt["segments"])
```

An empty list is falsy, so the filter is skipped and **all 9,327 rows (Apr–Jul 2026) reach the report**, including **1,185 Tank rows** carrying **10,069,350 litres**. Tank rows have blank machine labels and their size tiers ("200L", "500L", "2000L") sit in the `mould` field, so `rollup_by_mould` renders them as if they were moulds and sums litres into a column headed "Output" beside Moulding kg/pcs. The Moulding headline aggregate is therefore arithmetically wrong.
